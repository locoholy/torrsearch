# torrsearch — локальный поиск по торрент-трекерам

Мета-поиск, который опрашивает несколько трекеров сразу и показывает результаты
по мере их прихода. Работает только на localhost, зависимостей из npm нет —
нужен один Node.js.

## Запуск

```bash
./start.sh              # поднимает сервер и открывает браузер
```

или вручную:

```bash
node server.mjs         # http://127.0.0.1:8777
```

В меню приложений есть ярлык «Поиск торрентов».

## Источники

| id          | трекер         | что умеет                                       |
|-------------|----------------|-------------------------------------------------|
| `rutor`     | rutor.info     | magnet прямо в выдаче                           |
| `nnm`       | NNM-Club       | windows-1251, magnet тянется по клику           |
| `tpb`       | The Pirate Bay | JSON API; в последнее время часто отдаёт пусто  |
| `byrut`     | byrut (репаки) | не трекер, а сайт репаков; magnet считаем сами  |
| `rutracker` | RuTracker      | нужны куки из браузера, см. ниже                |

Галочки источников — в шапке страницы. Ненастроенный источник в списке остаётся,
но выключен и подписан подсказкой.

## Живые сиды

Цифры S/L в выдаче трекера — снимок на момент его последней переиндексации, а
byrut статистику не показывает вовсе: он не трекер, а сайт репаков, и рой живёт
на публичных трекерах, куда анонсится его `.torrent`.

Поэтому сиды можно спросить у самих трекеров, по протоколу scrape (BEP 15, UDP).
Опрашивается несколько публичных трекеров сразу, берётся тот, кто видит рой
полнее: каждый знает только тех пиров, что анонсились именно к нему.

* Строки byrut досчитываются **автоматически** после поиска — иначе их нельзя
  честно сравнить с остальными по колонке S/L.
* Кнопка **«Живые сиды»** в панели фильтра делает то же самое для всей выдачи,
  включая rutor/nnm/rutracker.
* Живые значения помечены точкой и подсказкой: с какого трекера и сколько раз
  раздачу скачали до конца (`completed` — признак живучести в долгую, лучше,
  чем сиды прямо сейчас).

Результаты кэшируются на 5 минут. Для byrut это не бесплатно: чтобы узнать
info-хеш, сервер качает сам `.torrent`, поэтому опрос идёт пачками по три.

### byrut — откуда берётся magnet

В выдаче byrut нет ни magnet-ссылок, ни статистики пиров — есть только `.torrent`
на странице игры. Поэтому по клику на строку сервер скачивает этот файл и считает
`btih` сам: SHA-1 от словаря `info` ровно в том виде, в каком он лежит в файле
(пересобирать нельзя — изменится порядок ключей и хеш не сойдётся). На сам поиск
это не влияет, лишний запрос уходит только когда вы жмёте «⬇» или «🔗».

До ответа трекеров в колонке «S / L» у byrut стоит счётчик скачиваний с сайта —
рисовать «↑0 ↓0» было бы враньём. Потом он заменяется живыми цифрами.

### rutracker — как включить

RuTracker закрыт двумя вещами сразу: Cloudflare-челленджем и обязательным логином.
Из скрипта это не обходится, но обе двери открывает один набор кук из браузера,
где вы уже залогинены:

1. Откройте rutracker в браузере и залогиньтесь (челлендж пройдёт сам).
2. DevTools → Network → любой запрос к rutracker.org → заголовок `Cookie`,
   скопируйте строку целиком (нужны как минимум `bb_session` и `cf_clearance`).
3. Положите её одной строкой в файл:

```bash
mkdir -p ~/.config/torrsearch
echo 'bb_session=...; cf_clearance=...' > ~/.config/torrsearch/rutracker.cookie
```

Файл читается на каждый поиск — перезапускать сервер не нужно, достаточно
перезагрузить страницу, чтобы галочка стала активной. Cloudflare привязывает
`cf_clearance` к User-Agent: если куки не срабатывают, пропишите тот же UA, что
и в браузере, в `RUTRACKER_UA`. Куки живут недолго — когда протухнут, источник
скажет «нужна настройка», а не «ошибка».

## Почему это не тормозит, как обычные такие сайты

- **Потоковая выдача (SSE).** Каждый трекер отдаёт результаты в браузер сразу,
  как ответил. Ждать самый медленный источник не нужно.
- **Видимое состояние каждого источника.** По каждому трекеру свой чип: `ищет`
  с бегущим секундомером → `32 найдено` / `пусто` / `не ответил` / `ошибка`.
  Никогда не бывает непонятно, идёт поиск или всё зависло.
- **Свой таймаут на попытку** (5 с, 2 попытки). Мёртвый трекер отваливается сам
  и не задерживает остальных.
- **Кэш на 10 минут.** Повтор того же запроса отвечает за 0 мс.
- **Никаких блокирующих запросов** в главном потоке и никаких фоновых анимаций.

## Настройки (переменные окружения)

| переменная         | по умолчанию                        | что делает                  |
|--------------------|-------------------------------------|-----------------------------|
| `PORT`             | `8777`                              | порт сервера                |
| `SOURCE_TIMEOUT`   | `5000`                              | таймаут одной попытки, мс   |
| `ATTEMPTS`         | `2`                                 | попыток на источник         |
| `MAGNET_TIMEOUT`   | `15000`                             | таймаут на добычу magnet, мс|
| `RUTRACKER_COOKIE` | —                                   | куки rutracker вместо файла |
| `RUTRACKER_UA`     | —                                   | UA под `cf_clearance`       |
| `CACHE_TTL`        | `600000`                            | время жизни кэша, мс        |
| `TRANSMISSION_RPC` | `http://127.0.0.1:9091/transmission/rpc` | адрес Transmission     |

## Кнопка «⬇» (добавить в Transmission)

Работает, если в Transmission включён удалённый доступ:
**Правка → Настройки → Удалённый доступ → Разрешить удалённый доступ**, порт 9091.
Без этого кнопка честно скажет, что RPC недоступен; кнопка «🔗» копирует magnet
в буфер в любом случае.

## Как добавить свой трекер

Создайте `adapters/мой.mjs` по образцу существующих:

```js
export default {
	id: 'мой',
	name: 'Мой трекер',
	site: 'https://example.org',
	async search(query, signal) {
		// вернуть массив { title, date, dateTs, sizeText, sizeBytes,
		//                 seeders, leechers, magnet, link }
	},
	// необязательно: если magnet нет в выдаче — тянется по клику
	async resolveMagnet(id, signal) { /* вернуть magnet-ссылку */ },
	// необязательно: false выключает галочку, пока источник не настроен
	ready: () => true,
};
```

и добавьте импорт в список `ADAPTERS` в начале `server.mjs`. Больше нигде ничего
править не нужно — фронтенд подхватит источник сам через `/api/sources`.
